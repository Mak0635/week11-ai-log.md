・採用
もしこの区別をせず、全部を同期処理として扱ってしまうと:

通信中は画面が完全に固まる
通信中は他のボタンも押せない
ユーザー体験が非常に悪くなる

逆に、全部を非同期処理として扱おうとすると:

単純な計算(1 + 1 など)まで「待ってから実行」という余計な手間がかかり、かえって遅くなる
コードも複雑になり、読みにくくなる　

良い質問です。理由は一言で言うと、「待つ必要がある処理」と「待つ必要がない処理」を同じ扱いにすると、アプリ全体が固まってしまうからです。

もし fetch が同期処理(=完全に待つ処理)だったら、通信が終わる数百ミリ秒〜数秒の間、画面上の他のボタンも、スクロールも、他のクリックも、一切反応しなくなります。ブラウザが「固まった」状態になるわけです。

普段皆さんがネットを見ていて、「画像の読み込み中でも他のリンクはクリックできる」「動画を再生しながらコメント欄にも書き込める」というのは、通信のような時間のかかる処理が非同期で行われているおかげです。

まとめ

区別する最大の理由は、「待つ必要がある処理」で画面全体を固まらせないためです。時間のかかる処理だけを「非同期」として特別扱いすることで、待っている間も他の操作を受け付けられる、快適なアプリケーションを作ることができます。

保留
・もし区別がなかったら何が起きるか

ブラウザ(JavaScript)は基本的に1つの処理しか同時に実行できません(これを「シングルスレッド」と言います)。1本の道路に1台の車しか走れないようなイメージです。

ここで、もし「通信」のような時間のかかる処理も、他の処理と同じように「順番待ち」させてしまうとどうなるか、例で見てみましょう。
